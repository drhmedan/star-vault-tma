# Star Vault — Matchmaking, Signaling & Ledger Server

سيرفر خفيف (Node) يشغّل على **Koyeb المجاني** ثلاث مسؤوليات على منفذ واحد:

| المسار | الوظيفة |
|---|---|
| `/match` | مطابقة WebSocket: طوابير → غرف (2..8) + ملء بالبوتات |
| `/peerjs` | إشارات WebRTC (استضافة ذاتية لـ PeerJS) |
| `/ledger/*` | دفتر الحسابات: رهان/تسوية/إلغاء — **السلطة الوحيدة لحركة النجوم** |
| `/health` | فحص صحّة + عدد المنتظرين + إحصاءات الدفتر |

حركة اللعب الفعلية **P2P بين الهواتف** ولا تمر عبر هذا السيرفر.

## دفتر الحسابات (Economy Ledger)

النجوم (العملة المرتبطة بأموال حقيقية) لا تتحرك إلا عبر هذا السيرفر:

| الطريقة | الوصف |
|---|---|
| `POST /ledger/stake` | يحجز الرهان في ضمان (escrow) قبل بدء المباراة — يرفض إن كان الرصيد ناقصاً (`409`) |
| `POST /ledger/settle` | يسجّل نتيجة المباراة ويدفع الجوائز المعتمدة (تكرار الطلب بنفس `matchId` آمن) |
| `POST /ledger/escrow/cancel` | يسترد ضماناً مفتوحاً إذا تعذّرت التسوية |
| `GET /ledger/player/:id` | الرصيد المعتمد للاعب |

**قواعد الجوائز (معتمدة على السيرفر):** خبرة = قتل×40 + ضرر×0.5 + دقائق×120؛ كؤوس +25/-15؛ غبار +200/+30؛ نجوم = الرهان×1.8 للفائز فقط.

**الحماية من الغش:** تقييد المباريات المسجّلة بالساعة، سقف نجوم يومي، تحقّق من حدود القيم (قتل ≤8، ضرر ≤30k)، وضمانات تنتهي تلقائياً وتُسترد بعد 30 دقيقة.

> حدود صادقة: اللعب P2P، فلا يمكن للسيرفر إثبات حدوث القتل فعلاً — لكنه يثبت **الاقتصاد** (من راهن، من فاز، وبقاء المدفوعات داخل القواعد).

**التخزين:** دفتر JSONL على قرص الحاوية (`server/data/ledger.jsonl`) — ينجو من إعادة التشغيل. الترحيل إلى TiDB يتم بإعادة بثّ السجل في جدولَي `escrows` و`match_ledger` (انظر `schema.sql`).

## التشغيل محلياً

```bash
cd server
npm install
npm start            # يستمع على المنفذ 8000
```

### متغيّرات البيئة (اختيارية)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | 8000 | منفذ الاستماع |
| `QUICK_MAX_HUMANS` | 2 | أقصى عدد بشر في غرفة الوضع السريع (1v1) |
| `QUICK_TOTAL_FIGHTERS` | 8 | إجمالي المقاتلين في المباراة (البشر + البوتات) |
| `QUICK_FILL_MS` | 30000 | نافذة التجميع بالمللي ثانية |
| `RANKED_MAX_HUMANS` | 8 | الوضع التنافسي يتطلب غرفة بشرية كاملة بلا بوتات |
| `RANKED_FILL_MS` | 60000 | نافذة التجميع التنافسي |
| `INITIAL_STARS` | 100 | رصيد النجوم الابتدائي للاعب الجديد في الدفتر |
| `MAX_STAKE` | 5000 | سقف الرهان الواحد |
| `MAX_STARS_PER_DAY` | 500 | سقف نجوم الجوائز اليومي لكل لاعب |
| `MAX_SETTLES_PER_HOUR` | 60 | سقف المباريات المسجّلة بالساعة |
| `ESCROW_TTL_MS` | 1800000 | مدة بقاء الضمان قبل الاسترداد التلقائي |
| `LEDGER_FILE` | `data/ledger.jsonl` | مسار ملف دفتر الحسابات |


## النشر على Koyeb (مجاني)

1. **Create Service** → **Dockerfile** → المجلد `server/`.
2. المنطقة: `Frankfurt` (المجانية)، الحجم المجاني (512MB).
3. المنفذ: `8000`.
4. بعد النشر خذ رابط الخدمة (مثل `https://xxx.koyeb.app`) وحدّث ثوابت الاتصال في واجهة اللعبة:
   - WebSocket: `wss://xxx.koyeb.app/match`
   - PeerJS: `host: xxx.koyeb.app, port: 443, path: '/peerjs', secure: true`
