# Star Vault — Matchmaking, Signaling & Ledger Server

سيرفر خفيف (Node) يشغّل على **Koyeb المجاني** ثلاث مسؤوليات على منفذ واحد:

| المسار | الوظيفة |
|---|---|
| `/match` | مطابقة WebSocket: طوابير → غرف (2..8) + ملء بالبوتات |
| `/peerjs` | إشارات WebRTC (استضافة ذاتية لـ PeerJS) |
| `/ledger/*` | دفتر الحسابات: رهان/تسوية/إلغاء — **السلطة الوحيدة لحركة النجوم** |
| `/api/create-invoice` | إنشاء فاتورة نجوم تيليجرام (هوية موثّقة) |
| `/webhook` | ويب هوك دفع تيليجرام: موافقة `pre_checkout_query` + إضافة النجوم عند `successful_payment` |
| `/health` | فحص صحّة + عدد المنتظرين + إحصاءات الدفتر |

حركة اللعب الفعلية **P2P بين الهواتف** ولا تمر عبر هذا السيرفر.

## دفتر الحسابات (Economy Ledger)

النجوم (العملة المرتبطة بأموال حقيقية) لا تتحرك إلا عبر هذا السيرفر:

| الطريقة | الوصف |
|---|---|
| `POST /ledger/stake` | يحجز الرهان في ضمان (escrow) قبل بدء المباراة — يرفض إن كان الرصيد ناقصاً (`409`) |
| `POST /ledger/settle` | يسجّل نتيجة المباراة ويدفع الجوائز المعتمدة (تكرار الطلب بنفس `matchId` آمن) |
| `POST /ledger/escrow/cancel` | يسترد ضماناً مفتوحاً إذا تعذّرت التسوية |
| `POST /ledger/purchase` | خصم نجوم لشراء متجر (مثل الممر المميز) — تكرار آمن بـ `purchaseId` |
| `POST /ledger/grant` | منح نجوم لمكافأة (مثل نجوم الممر) — تكرار آمن بـ `grantId` ومقيّد بالسقف اليومي |
| `GET /ledger/player/:id` | الرصيد المعتمد للاعب |

**قواعد الجوائز (معتمدة على السيرفر):** خبرة = قتل×40 + ضرر×0.5 + دقائق×120؛ كؤوس +25/-15؛ غبار +200/+30؛ نجوم = الرهان×1.8 للفائز فقط.

**الحماية من الغش:** تقييد المباريات المسجّلة بالساعة، سقف نجوم يومي، تحقّق من حدود القيم (قتل ≤8، ضرر ≤30k)، وضمانات تنتهي تلقائياً وتُسترد بعد 30 دقيقة.

> حدود صادقة: اللعب P2P، فلا يمكن للسيرفر إثبات حدوث القتل فعلاً — لكنه يثبت **الاقتصاد** (من راهن، من فاز، وبقاء المدفوعات داخل القواعد).

## التحقق من هوية تيليجرام (Telegram Identity)

كل طلب إلى `/ledger/*` يحمل ترويسة `X-Telegram-Init-Data` (سلسلة `initData` الموقّعة من تيليجرام). عند ضبط `BOT_TOKEN` يتحقق السيرفر من توقيع HMAC-SHA256 وفق خوارزمية تيليجرام الرسمية:

1. `secret_key = HMAC_SHA256("WebAppData", BOT_TOKEN)`
2. `data_check_string` = الحقول مرتبة أبجدياً بصيغة `key=value` مفصولة بـ `\n` (عدا `hash`)
3. مطابقة `hash` مع `HMAC_SHA256(secret_key, data_check_string)` + التحقق من حداثة `auth_date`

وعندئذٍ يكون **المعرّف المعتمد للاعب هو `user.id` من التوقيع** — أي محاولة لإرسال `playerId` مختلف تُرفض (`403`)، وقراءة رصيد لاعب آخر مرفوضة، والطلبات بلا توقيع صالح تُرفض (`401`). بدون `BOT_TOKEN` يعمل السيرفر في **وضع تطوير** (بلا تحقق) للاختبار المحلي.

**بوابة الدفع:** نقاط إضافة النجوم (`/ledger/topup`) محجوزة لويب هوك الدفع في الإنتاج — العميل المُوثَّق لا يستطيع إضافة نجوم لنفسه إلا إذا ضُبط `ALLOW_CLIENT_TOPUP=1` (للتطوير فقط).

## دفع نجوم تيليجرام (Telegram Stars)

تدفق شراء النجوم بالكامل عبر تيليجرام (إلزامي على iOS داخل التطبيقات المصغّرة):

1. العميل يطلب `/api/create-invoice` (بهوية تيليجرام موثّقة) → السيرفر يستدعي `createInvoiceLink` بعملة `XTR` وحمولة `SV-{userId}-{packageId}-{nonce}`.
2. العميل يفتح الرابط عبر `Telegram.WebApp.openInvoice`.
3. تيليجرام يرسل `pre_checkout_query` (يوافق عليه السيرفر بعد التحقق من السعر والعملة) ثم `message.successful_payment`.
4. الويب هوك يضيف النجوم فوراً (الرصيد + المكافأة) عبر `ledger.topup` — **تكرار التسليم آمن** (نفس الحمولة = نفس العملية) وأي مبلغ مزيّف يُرفض.

الحزم المعتمدة على السيرفر (`server/payments.mjs`) تطابق حزم العميل: 50 / 150 / 500 / 1500 نجمة (+5 / +25 / +100 / +400 مكافأة).

**تفعيل الويب هوك تلقائياً عند الإقلاع** عند ضبط `BOT_TOKEN` + `WEBHOOK_URL` (يستدعي `setWebhook` بـ `allowed_updates=["message","pre_checkout_query"]`).

**التخزين:** دفتر JSONL على قرص الحاوية (`server/data/ledger.jsonl`) — ينجو من إعادة التشغيل. عند ضبط `DATABASE_URL` يصبح **TiDB هو مصدر الحقيقة الدائم** (ينجو من أي إعادة نشر) ويبقى JSONL احتياطياً للكتابة أثناء انقطاع القاعدة (انظر `schema.sql`).

## قاعدة TiDB (المصدر الدائم للحسابات)

1. أنشئ كلاستر **TiDB Serverless Starter** مجاناً، ونفّذ `server/schema.sql` من **SQL Editor** في المتصفح.
2. أضف متغير `DATABASE_URL` (أو `TIDB_HOST/PORT/USER/PASSWORD/NAME`) — الخادم يتصل تلقائياً عند الإقلاع، و`/health` يعرض `"db": "tidb"`.
3. لنقل دفتر قائم إلى TiDB مرة واحدة: `npm run migrate` (تكراره آمن).
4. عند انقطاع TiDB يستمر الخادم على ملف JSONL، ويعيد التعبئة تلقائياً عند عودته (كل عملية لها مفتاح طبيعي يمنع التكرار).

### متغيّرات البيئة (اختيارية)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | 8000 | منفذ الاستماع |
| `QUICK_MAX_HUMANS` | 2 | أقصى عدد بشر في غرفة الوضع السريع (1v1) |
| `QUICK_TOTAL_FIGHTERS` | 8 | إجمالي المقاتلين في المباراة (البشر + البوتات) |
| `QUICK_FILL_MS` | 30000 | نافذة التجميع بالمللي ثانية |
| `RANKED_MAX_HUMANS` | 8 | الوضع التنافسي يتطلب غرفة بشرية كاملة بلا بوتات |
| `RANKED_FILL_MS` | 60000 | نافذة التجميع التنافسي |
| `INITIAL_STARS` | 100 | رصيد النجوم الابتدائي للاعب الجديد في الدفتر |
| `MAX_STAKE` | 5000 | سقف الرهان الواحد |
| `MAX_STARS_PER_DAY` | 500 | سقف نجوم الجوائز اليومي لكل لاعب |
| `MAX_SETTLES_PER_HOUR` | 60 | سقف المباريات المسجّلة بالساعة |
| `ESCROW_TTL_MS` | 1800000 | مدة بقاء الضمان قبل الاسترداد التلقائي |
| `LEDGER_FILE` | `data/ledger.jsonl` | مسار ملف دفتر الحسابات |
| `BOT_TOKEN` | *(فارغ)* | رمز البوت — عند ضبطه يُفعَّل التحقق من هوية تيليجرام على كل `/ledger/*` |
| `INITDATA_MAX_AGE_MS` | 86400000 | أقصى عمر مقبول لجلسة `initData` (افتراضياً 24 ساعة) |
| `ALLOW_CLIENT_TOPUP` | `0` | `1` يسمح للعميل بإضافة نجوم (للتطوير فقط؛ الإنتاج عبر ويب هوك الدفع) |
| `WEBHOOK_URL` | *(فارغ)* | الرابط العام للويب هوك (مثل `https://sv-xxx.koyeb.app/webhook`) — يُسجَّل عند الإقلاع |
| `WEBHOOK_SECRET` | *(فارغ)* | سرّ مصادقة تحديثات تيليجرام (يُطابَق مع ترويسة `X-Telegram-Bot-Api-Secret-Token`) |
| `TELEGRAM_API_BASE` | `https://api.telegram.org` | قاعدة Bot API (للتعديل في الاختبارات فقط) |
| `CORS_ORIGIN` | `*` | أصل الواجهة المسموح له باستدعاء الـ API (التحقق عبر initData لا عبر الكوكيز) |
| `DATABASE_URL` | *(فارغ)* | كونكشن سترينغ TiDB (`mysql://…`) — عند ضبطه يصبح TiDB مصدر الحقيقة |
| `TIDB_HOST/PORT/USER/PASSWORD/NAME` | *(فارغة)* | بديل عن `DATABASE_URL` كمتغيرات منفصلة |
| `TIDB_SSL_CA` | *(فارغ)* | مسار ملف CA مخصّص لاتصال TLS (اختياري) |

## النشر على Koyeb (مجاني)

1. **Create Service** → **Dockerfile** → المجلد `server/`.
2. المنطقة: `Frankfurt` (المجانية)، الحجم المجاني (512MB).
3. المنفذ: `8000`.
4. متغيّرات البيئة المطلوبة: `BOT_TOKEN` + `WEBHOOK_URL` + `WEBHOOK_SECRET` (انظر `.env.example`). متغيّر `CORS_ORIGIN` (`*` افتراضياً) يسمح للواجهة على Vercel باستدعاء الـ API من أصل آخر.
5. بعد النشر خذ رابط الخدمة (مثل `https://xxx.koyeb.app`) وضعه في `VITE_GAME_SERVER` بواجهة اللعبة (Vercel)، ثم تحقّق:

```bash
GAME_SERVER=https://xxx.koyeb.app node server/deploy-smoke.mjs
```

الدليل الكامل خطوة بخطوة في `DEPLOY.md`.
